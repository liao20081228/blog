# 名称
grep, egrep, fgrep, rgrep——打印与模式匹配的行

# 概览
**grep** \[<u>OPTION</u>...] <u>PATTERNS </u>\[<u>FILE</u>...]
**grep** \[<u>OPTION</u>...] **-e** <u>PATTERNS </u>... \[<u>FILE</u>...]
**grep** \[<u>OPTION</u>...] **-f** <u>PATTERN_FILE </u>... \[<u>FILE</u>...]

# 描述

grep 在每个<u>FILE</u>中搜索<u>PATTERNS </u>。在概览的第一种形式（如果未提供 `-e` 或 `-f` 选项，则使用该形式）， 第一个操作数<u>PATTERNS </u>是一个或多个由换行符分隔的模式，grep 打印与模式匹配的每一行。 通常，当在 shell 命令中使用 **grep** 时，应将 <u>PATTERN</u>S 加上引号。

<u>FILE</u>为 “-”代表标准输入。 如果未给出 <u>FILE</u>，则递归搜索将检查工作目录，非递归搜索将读取标准输入。

Debian 还包括变种程序**egrep**、**fgrep** 和**rgrep**。 这些程序分别与`grep -E`、`grep -F` 和 `grep -r` 相同。 这些变体在上游已被弃用，但 Debian 提供了向后兼容性。 出于可移植性的原因，建议避免使用变种程序，而使用带有相关选项的 **grep**。

# 选项
**通用程序信息**
- **--help** 
输出使用信息并退出。
- **-V**，**--version** 
输出**grep**的版本号并退出。

**模式语法**
- **-E**，**--extended-regexp**	
将 <u>PATTERNS</u> 解释为扩展正则表达式（EREs，见下文）。
- **-F**，**--fixed-strings**	
将 <u>PATTERNS</u>解释为固定字符串，而不是正则表达式。
- **-G**，**--basic-regexp**	
 将 <u>PATTERNS</u>解释为基本正则表达式（BREs，见下文）。 这是默认设置。
- **-P**，**--perl-regexp**
将 <u>PATTERNS</u>解释为与 Perl 兼容的正则表达式 (PCREs)。 当与 `-z (--null-data)` 选项结合使用时，此选项是实验性的，`grep -P` 可能会警告未实现的功能。

**匹配控制**
- **-e** <u>PATTERNS</u>, **--regexp**=<u>PATTERNS</u>
将 <u>PATTERNS </u>用作模式。如果多次使用此选项，或将其与 `-f`（`--file`）选项组合使用，则搜索所有给出的模式。此选项可用于保护以“-”开头的模式。
- **-f** <u>FILE</u>, **--file**=<u>FILE</u>
从 <u>FILE </u>中获取模式，每行一个。如果多次使用此选项，或将其与 `-e`（`--regexp`）选项组合使用，则搜索所有给出的模式。空文件包含零个模式，因此不匹配任何内容。如果 FILE 为 `-`，则从标准输入读取模式。
- **-i**, **--ignore-case**
忽略模式和输入数据中的大小写差异，使仅大小写不同的字符彼此匹配。
- **--no-ignore-case**
不忽略模式和输入数据中的大小写差异。这是默认行为。此选项适用于传递给已经使用 `-i` 的 shell 脚本，以取消其效果，因为这两个选项会相互覆盖。
- **-v**, **--invert-match**
反转匹配的含义，以选择不匹配的行。
- **-w**, **--word-regexp**
仅选择包含构成完整单词的匹配的行。其判定条件是：匹配的子串必须位于行首，或前面是非单词构成字符；同样，它必须位于行尾，或后面是非单词构成字符。单词构成字符是字母、数字和下划线。如果同时指定了 `-x`，则此选项无效。
- **-x**, **--line-regexp**
仅选择与整行完全匹配的匹配项。对于正则表达式模式，这相当于给模式加上括号，然后在其前后分别加上 `^` 和 `$`。

**通用输出控制**
- **-c**, **--count**
抑制常规输出；改为打印每个输入文件的匹配行数。与 `-v`，`--invert-match` 选项（见上文）一起使用时，统计不匹配的行数。
- --**color\[=<u>WHEN</u>]**, **--colour[=<u>WHEN</u>]**
用转义序列包围匹配的（非空）字符串、匹配行、上下文行、文件名、行号、字节偏移量以及分隔符（用于字段和上下文行组），以便在终端中以彩色显示它们。颜色由环境变量 **GREP_COLORS** 定义。<u>WHEN </u>可为 `never`、`always` 或 `auto`。
- **-L**, **--files-without-match**
抑制常规输出；改为打印每个原本不会输出任何内容的输入文件名。
- **-l**, **--files-with-matches**
抑制常规输出；改为打印每个原本会输出内容的输入文件名。扫描每个输入文件时，在首次匹配后即停止。
- **-m <u>NUM</u>**, **--max-count=<u>NUM</u>**
在读到 <u>NUM </u>个匹配行后停止读取文件。如果 <u>NUM </u>为零，**grep** 会立即停止，不读取输入。<u>NUM </u>为 -1 时视为无穷大，**grep** 不会停止；这是默认行为。如果输入是来自常规文件的标准输入，并且已输出 <u>NUM </u>个匹配行，则 **grep** 在退出前会确保标准输入定位到最后一条匹配行之后，无论是否存在尾随上下文行。这使调用进程能够继续搜索。当 **grep** 在 <u>NUM</u>个匹配行后停止时，它会输出任何尾随的上下文行。当同时使用 `-c` 或 `--count` 选项时，**grep** 输出的计数不会大于 NUM。当同时使用 `-v` 或 `--invert-match` 选项时，**grep** 在输出 <u>NUM </u>个不匹配行后停止。
- **-o**, **--only-matching**
仅打印匹配行中匹配的（非空）部分，每个这样的部分单独输出一行。
- **-q**, **--quiet**, **--silent**
安静模式；不向标准输出写入任何内容。如果找到任何匹配，即使检测到错误，也立即以零状态退出。另请参见 `-s` 或 `--no-messages` 选项。
- **-s**, **--no-messages**
抑制关于文件不存在或不可读的错误消息。

# 正则表达式

正则表达式是一种描述一组字符串的模式。正则表达式的构造方式类似于算术表达式，即使用各种运算符将较小的表达式组合起来。

**grep** 理解三种不同版本的正则表达式语法：“基本”（BRE）、“扩展”（ERE）和“Perl”（PCRE）。在 GNU **grep** 中，基本正则表达式和扩展正则表达式只是同一模式匹配功能的不同记法。在其他实现中，基本正则表达式通常比扩展正则表达式功能弱，不过偶尔也相反。以下描述适用于扩展正则表达式；基本正则表达式的差异在最后总结。Perl 兼容正则表达式具有不同的功能，记录在 **pcre2syntax(3)** 和 **pcre2pattern(3)** 中，但仅在启用了 PCRE 支持时才有效。

基本的构建块是匹配单个字符的正则表达式。大多数字符，包括所有字母和数字，都是匹配自身的正则表达式。任何具有特殊含义的元字符都可以通过在其前面加反斜杠来引用。

句点 `.` 匹配任意单个字符。它是否匹配编码错误未作规定。

**字符类和方括号表达式**

<u>方括号表达式</u>是由 `[` 和 `]` 包围的字符列表。它匹配该列表中的任意单个字符。如果列表的第一个字符是脱字符 `^`，则它匹配不在该列表中的任意字符；它是否匹配编码错误未作规定。例如，正则表达式 `[0123456789]` 匹配任意单个数字。

在<u>方括号表达</u>式内，<u>范围表达式</u>由两个字符组成，中间用连字符分隔。在默认的 C 语言环境中，它匹配按 ASCII 顺序出现在这两个字符之间的任意单个字符，包括两端字符。例如，`[a-d]` 等价于 `[abcd]`。在其他语言环境中，行为未作规定：`[a-d]` 可能等价于 `[abcd]` 或 `[aBbCcDd]` 或其他某个方括号表达式，或者它可能无法匹配任何字符，或者它匹配的字符集可能不稳定，或者它可能无效。要获得方括号表达式的传统解释，可以将 `LC_ALL` 环境变量设置为值 `C`，从而使用 C 语言环境。

最后，在方括号表达式内预定义了一些命名字符类，如下所示。它们的名称不言自明，分别是 `[:alnum:]`、`[:alpha:]`、`[:blank:]`、`[:cntrl:]`、`[:digit:]`、`[:graph:]`、`[:lower:]`、`[:print:]`、`[:punct:]`、`[:space:]`、`[:upper:]` 和 `[:xdigit:]`。例如，`[[:alnum:]]` 表示当前语言环境中的数字和字母字符类。在 C 语言环境和 ASCII 字符集编码中，这与 `[0-9A-Za-z]` 相同。（注意，这些类名中的方括号是符号名称的一部分，必须额外包含在界定方括号表达式的方括号之内。）大多数字符在方括号表达式内会失去其特殊含义。要包含字面量 `]`，应将其放在列表的最前面。类似地，要包含字面量 `^`，应将其放在除最前面以外的任意位置。最后，要包含字面量 `-`，应将其放在最后。

**锚定**

脱字符 `^` 和美元符号 `$` 是元字符，分别匹配行首和行尾的空字符串。

**反斜杠字符和特殊表达式**
符号 `\<` 和 `\>` 分别匹配单词开头和结尾的空字符串。符号 `\b` 匹配单词边缘的空字符串，而 `\B` 匹配不在单词边缘的空字符串。符号 `\w` 是 `[_[:alnum:]]` 的同义词，`\W` 是 `[^_[:alnum:]]` 的同义词。

**重复**
正则表达式后面可以跟若干重复运算符之一：
`?`      前一项可选，最多匹配一次。
`*`      前一项将匹配零次或多次。
`+`      前一项将匹配一次或多次。
`{n}`    前一项恰好匹配 n 次。
`{n,}`   前一项匹配 n 次或更多次。
`{,m}`   前一项最多匹配 m 次。这是 GNU 扩展。
`{n,m}`  前一项至少匹配 n 次，但不超过 m 次。

**连接**
 两个正则表达式可以连接；得到的正则表达式匹配由两个分别匹配所连接表达式的子串连接而成的任意字符串。

**备选**
两个正则表达式可以用中缀运算符 `|` 连接；得到的正则表达式匹配与任一备选表达式匹配的任意字符串。

**优先级**
重复优先于连接，连接又优先于备选。整个表达式可以用括号括起来，以覆盖这些优先级规则并形成子表达式。

**反向引用和子表达式**
反向引用 `\n`（其中 n 是一位数字）匹配该正则表达式的第 n 个括号子表达式先前匹配的子串。

**基本正则表达式与扩展正则表达式**
在基本正则表达式中，元字符 `?`、`+`、`{`、`|`、`(` 和 `)` 失去其特殊含义；应改用带反斜杠的版本 `\?`、`\+`、`\{`、`\|`、`\(` 和 `\)`。
