# 两种编程
vibe coding：通过对话迭代，将**模糊需求**逐步变成实际产品。核心要素：需求探索、对话累积、迭代优化、上下文管理

spec coding：需求明确时，**先写规范**在让AI按规范执行。四个阶段：vibe探索、需求整理、规范形成、规范执行

# 项目配置

## 项目概述
这是一个待办清单应用，帮助用户管理日常任务。

## 技术栈
- 前端：React 18 + TypeScript 5
- 样式：Tailwind CSS 3
- 状态管理：Zustand
- 测试：Vitest

## 项目结构
- src/components：React 组件
- src/hooks：自定义 Hooks
- src/utils：工具函数

## src/types：TypeScript 类型定义

## 通用规范
- 使用函数式组件，不用 class 组件
- 所有函数必须在 TypeScript 类型声明
- 组件文件使用 PascalCase 命名
- 工具函数使用 camelCase 命名
- 使用中文注释

## 禁止事项
- 不要使用 'any' 类型
- 不要使用 jQuery
- 不要在组件中直接写内联样式（使用 Tailwind）
- 不要使用 'var'，使用 'const' 或 'let'

## 常用命令
- 开发：npm run dev
- 构建：npm run build
- 测试：npm test

# AI不听话

- 过度发挥

- 自相矛盾
- 幻觉：包幻觉、API幻觉、逻辑幻觉、版本幻觉
- 死循环

应对方式：
- 精确指出问题：SBI
- 给出正确示例
- 分步重做
- 换一种问法
 
# Agent
AI Agent = LLM（核心引擎）+ 四大组件（Memory + Planning + Tools + Action）

# harness
**skills**：封装特定任务能力的可复用模块

**rules**：给agents设置的长期行为准则。**约束AI行为**的结构化指令，确保Agent的输出符合团队规范和安全要求。长期通用的行为准则。

**plans**：agents针对具体任务生成的执行步骤序列

**specs**：对任务、输出、流程的详细要求文档。**可被AI读取和执行的明确、结构化、可验证的标准**。短期具体的任务要求。
- API接口规范
- 编码规范
- 架构决策
